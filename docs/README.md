# Documentazione OCIO

Manteniamo pochi documenti, ciascuno con uno scopo preciso.

| Documento | Contiene | Non contiene |
| --- | --- | --- |
| `README.md` | avvio e uso del progetto | backlog o decisioni storiche |
| `implementation-plan.md` | roadmap e link alle issue | specifiche dei ticket |
| `CONTEXT.md` | termini e confini di dominio | dettagli di implementazione |
| `docs/adr/` | decisioni tecniche durevoli e il loro perché | esplorazione estesa |
| `docs/research/` | evidenza temporanea per una decisione | documentazione di prodotto |

## Regola pratica

Una issue descrive lavoro da fare. Un ADR registra una scelta già fatta. Una research risponde a una domanda aperta e scompare quando la sua conclusione è catturata altrove.

Scrivi in linguaggio tecnico semplice. Usa un esempio breve solo quando chiarisce una regola ambigua.
