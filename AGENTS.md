## Engineering principles

- Prefer the smallest clear change that fully solves the requested problem.
- Write as little code as practical; reuse existing abstractions before introducing new ones.
- Avoid over-engineering: do not add speculative abstractions, configurability, dependencies, or infrastructure without a concrete current need.

## Documentation principles

- Keep documentation concise, current, and high-level. Put implementation work and its acceptance criteria in GitHub Issues.
- Use simple technical language. Explain only what is needed to make a decision or perform a task.
- Prefer a small concrete example when it removes ambiguity; do not add filler or long background sections.
- Treat research notes as temporary evidence. Record enduring technical decisions as short ADRs, then archive or remove superseded research.
